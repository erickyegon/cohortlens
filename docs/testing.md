# Testing

- `make test`: pytest unit + integration (Testcontainers, Postgres 16), telemetry leak test, Vitest, agent replay tests.
- `make e2e`: Playwright against Compose (separate CI job).
- `make verify-seed`: load the committed seed into a throwaway Postgres 16 container and assert the reference cohort (920 → 481).
- Quality gates: 80% line coverage on `api/app/cohort_engine/`; Ruff + ESLint clean; no real Anthropic API calls.
- Dev dependencies: `pip install -r api/requirements-dev.txt` (Docker required for Testcontainers).

## CI

`.github/workflows/ci.yml` runs on every pull request and every push to `main`. Four jobs, each a **required check on `main`** (branch protection also applies to admins, so a red check blocks the merge button):

| Check | What it does | Local equivalent |
|---|---|---|
| `lint` | Ruff (`ruff.toml`, includes `S608` for SQL built from strings), ESLint, `tsc --noEmit` | `make lint` |
| `test` | `make test` (pytest incl. Testcontainers suites; needs Docker) then the seed integration test against the committed seed | `make test`, `make verify-seed` |
| `build` | Builds the api and web images (no push) with `SERVICE_VERSION=<sha>` | `docker compose build` |
| `smoke` | Clean `docker compose` start: order, seed, role privileges, nginx proxy, persistence across restart | `bash scripts/smoke_compose.sh --clean` |

Ruff is pinned (`ruff==...` in `ci.yml` and `api/requirements-dev.txt`; keep them in sync). Playwright e2e is a separate job planned in #32. Actions are pinned to major tags; digest pinning is deferred to the deploy epic.

## Truth fixture

`api/tests/fixtures/truth_fixture.sql` holds 23 hand-built patients (generated by `api/tests/fixtures/build_truth_fixture.py`; edit the generator, not the SQL). Every patient exists to exercise one criterion or boundary of the reference cohort in `docs/spec.md` §7. The expected counts below were worked out by hand, not taken from the code under test; `api/tests/integration/test_truth_fixture.py` asserts them against `data/etl/example_cohort.sql`, the oracle the cohort engine must reproduce.

Reference cohort attrition on the fixture: **22 → 18 → 16 → 13 → 11 → 10**. (Through the API the final 10 would be shown as `"<11"`, so engine-level tests must assert on internal counts before suppression.)

| Step | Count | Removed here (and why) |
|---|---|---|
| First lisinopril exposure (index) | 22 | P4: enalapril only, never lisinopril |
| ≥365 days prior observation | 18 | P5: 112 days of observation · P7: 364 days · P22: observation ends the day before index · P23: gap between two observation periods, the one containing index is 102 days old (P6 has exactly 365 days and stays in) |
| No ACE inhibitor in prior 365 days | 16 | P8: enalapril 101 days before · P10: enalapril exactly 365 days before (P9 had it 401 days before and stays in) |
| Hypertension on or before index | 13 | P11: none · P12: diagnosed the day after index · P19: hypertension only after the *first* lisinopril (tests first-occurrence index); P13 has it on the index date and stays in |
| No prior heart failure | 11 | P14: heart failure before index · P16: chronic CHF, a descendant concept (P15 has it only after index, P21 on the index date itself; both stay in because the rule is strictly *before*) |
| Age ≥ 50 at index | **10** | P17: 49, turns 50 the day after index (P18 turns 50 exactly on the index date and stays in) |

Final cohort: P1, P2, P3, P6, P9, P13, P15, P18, P20, P21.

Criterion types and the patients that cover them:

| Criterion type | Patients |
|---|---|
| Descendant expansion, drug (ingredient → clinical drug, combination product) | P1, P2 (20 mg), P3 (hydrochlorothiazide combination) |
| Descendant expansion, condition | P2 (hypertension child concept), P16 (heart failure child concept) |
| First-occurrence index | P19 |
| Observation window boundary (365 vs 364 days) | P6, P7 |
| Observation end before index; several observation periods with a gap | P22, P23 |
| Washout window boundary (365 vs 401 days) | P9, P10 |
| Same-day event (`≤ index` for hypertension) | P13 |
| Same-day event must NOT count (`< index` for heart failure) | P21 |
| Event after index must not count | P12, P15 |
| Age boundary (birthday on / one day after index) | P17, P18 |
| Death after index does not remove a patient | P20 |

Known gaps (not covered by the fixture's own patients): the seed vocabulary has no hypertension child concept (P2 uses one the fixture adds by hand); NULL month or day of birth (the oracle would count the person one year older; the seed always populates them) and ACE washout through an ingredient-level concept (no ancestor row from the class to the ingredient in the trimmed vocabulary; clinical drugs are what appear in exposures).

Schema drift guard: `test_fixture_columns_match_the_etl_output_columns` compares the fixture's `cdm` columns with the columns the ETL writes into the seed.

`make test` skips the two seed tests unless `COHORTLENS_TEST_DSN` is set; `make verify-seed` runs them against the committed seed. CI (issue #16) must install `api/requirements-dev.txt` and provide Docker, because the Testcontainers tests fail rather than skip without them.

Rules for extending the fixture: add a patient and a row in the tables above in the same change, regenerate the SQL, and update the expected numbers in the test. Never derive an expected number by running the code under test.
